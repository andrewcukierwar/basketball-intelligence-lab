# Canonical NBA data contracts

**Status:** Proposed v0.1 for [issue #3][issue3]. **Classification:** Original BIL design. The [source audit](data-sources.md) supplies the observed fields and limitations. This contract defines logical schemas and invariants for the [2022–23 pilot][issue5]. The [evaluation contract][issue4] owns forecast origins, frozen split dates, experiment manifests and models.

## Types and conventions

- `id` and `text` are UTF-8 strings. IDs are nonempty, opaque to joins and preserved as strings through CSV, JSON and Parquet. Use the identity rules below at the provider boundary.
- `i16`, `i32` and `i64` are signed integers. Use nonnegative checks for real clock values, sequence numbers and totals. Use millisecond integers for elapsed basketball time and player minutes. Score deltas are signed integers.
- `date` is an ISO calendar date. `instant` is a UTC timestamp with microsecond precision. Source timezone and timestamp precision are retained in provenance. When a source provides a date only, preserve the date and leave the corresponding instant null.
- `decimal` is fixed point `DECIMAL(20,6)` for observations and exposures. `f64` is a finite double for derived feature values. `bool` is Boolean. `T[]` is an ordered array of non-null values. A trailing `?` marks a nullable field. `enum{…}` lists the allowed values.
- Every independently versioned table has a logical key and a positive `revision` suffix on its physical key. Uniqueness and foreign keys are evaluated inside a resolved view or within the same game stream, as applicable. Raw input and each canonical revision are immutable. All listed fields are required unless marked nullable.

## Identity, season and crosswalk

| Entity and canonical key | Rule and scope |
| --- | --- |
| `player(player_id: id)` | The positive decimal NBA person ID for a verified player, stored as a string without leading zeros. A team change, name change or different display spelling preserves the player ID. Coaches and placeholder codes stay in source actor metadata. |
| `team(team_id: id)` | The positive decimal NBA team ID stored as a string without leading zeros. Keep observed names and abbreviations in dated source metadata. Team-side membership uses the game and the team ID. |
| `game(game_id: id)` | The official ten-digit NBA game ID. Restore leading zeros only for an explicitly documented NBA-ID field on a source that strips them. A non-NBA provider identifier requires an explicit crosswalk. Changes to a scheduled time preserve identity when the league keeps the ID. Record an explicit supersession when an official reschedule uses a different ID. |
| `season(start_year: i16, league: enum{NBA})` | Key is `(league, start_year)`. For the pilot, `2022` means 2022–23. Bentes and Bill Mill use the ending year, while Shufinskiy uses the starting year. Normalize based on the specific input. |
| `season_type` on `game` | `enum{preseason, regular, play_in, playoffs, all_star, other, unknown}`. Explicitly map provider values and assert agreement with the official game identity where possible. Observed pilot keys use `002` for regular, `004` for playoffs, and the separate game logs use `005` for play-in. The pilot includes regular and playoffs only. A label or code conflict stays flagged until resolved. [Source validation](research/nba-source-validation.md) |

`id_mapping` is independently versioned. Its logical key is `(namespace: id, entity_type: enum{player,team,game}, source_id: id, valid_from: date)`. Fields are `canonical_id: id`, `valid_until: date?` (exclusive), and the version fields below. A namespace identifies the upstream ID system, while the artifact identifies the publisher that delivered it. An as-of join requires a visible mapping version whose validity interval contains the record's league date. Intervals for the same source ID and entity cannot overlap in a resolved view. Official NBA IDs resolve directly after field-level validation. Cross-provider game mappings use the official ID where possible, otherwise use date, teams, home/away and tip time to find a candidate and require unambiguous confirmation. Names and abbreviations can help locate evidence. An unresolved ID or ambiguous crosswalk goes to the exception report, and no accepted row receives an invented ID.

| Pilot input | ID fields at the provider boundary |
| --- | --- |
| Shufinskiy NBA Stats V2 | Map `GAME_ID`, `PLAYER1_ID` through `PLAYER3_ID`, and corresponding `PLAYER*_TEAM_ID` fields after validating actor roles and sentinels. `EVENTNUM` is a source event identifier. |
| Shufinskiy NBA Stats V3 | Map `gameId`, `personId` and `teamId` in the NBA namespace. Scope `actionNumber` to this provider and game. |
| Bill Mill NBA game logs | Map `game_id`, `team_id`, `opp_team_id` and player-game `player_id` directly after validation. The home flag informs team-side reconciliation. |
| Bentes comparison tables | Map NBA `game_id`. Treat lineup names and team abbreviations as comparison labels until resolved to canonical IDs within the game roster. |

## Provenance and time

| Record | Key and typed fields |
| --- | --- |
| `source_artifact` | `artifact_id: id`. Fields `source_id: id`, `upstream_namespace: id`, `uri: text`, `source_revision: text?`, `sha256: text` (64 lowercase hex), `size_bytes: i64`, `retrieved_at: instant`, `rights_ref: id`. The same byte digest can occur in distinct publisher artifacts. References to the rights ledger apply to the particular acquisition and use. |
| `source_ref` | Struct `{artifact_id: id, locator: text}`. The locator identifies a CSV row, a Parquet row within a pinned file, a JSON path, or the external evidence referenced in a decision. Artifacts are kept outside Git when restricted. |
| `version fields` | `revision: i32`, `available_at: instant?`, `availability_basis: enum{published,capture_bound,unknown}`, `ingested_at: instant`, `source_refs: source_ref[]` (nonempty), `change: enum{upsert,retract}`. Require evidence for `published` or `capture_bound`. Retractions contain the same logical key, revision and provenance. Business payload for a retraction may be absent. |

For game-scoped observations, `observed_date` is the official NBA played date in the Eastern calendar, even if the game crosses midnight. `observed_at` is the actual observation instant when known. A game clock locates an event within a game and cannot reconstruct wall-clock observation time. A postponed game's earlier scheduled date lives in the earlier schedule revision. Record when a date denotes the schedule rather than an actual game. Store UTC instants, including tip times, and convert Eastern day boundaries with `America/New_York`, including daylight saving transitions.

`retrieved_at` is when acquisition of the raw bytes completed. `ingested_at` is when BIL recorded the canonical revision. `available_at` is the earliest evidenced instant at which that exact revision of the source facts can be considered usable. A timestamped publication identifies the revision itself. A successful timestamped capture establishes a conservative bound for those bytes. A current archive can support retrospective research even if there is no evidence its bytes were available at a historical cutoff. A file's last-modified timestamp, the game date, or the parsing time is insufficient by itself. `availability_basis = unknown` requires null `available_at` and excludes the revision from strict historical views.

For a strict cutoff `C`, filter by known `available_at <= C`, take the highest authoritative visible revision per logical key, then apply retractions and status filters. A filtered revision leaves the record ineligible at that cutoff. Revision order follows canonical source authority and correction lineage. An unverified conflicting update stays quarantined. A played-game observation additionally requires evidence that it occurred before `C`. A known `finalized_at < C` establishes that a complete final game's events are earlier even if the event wall clocks are null. With only an Eastern played date, require `observed_date < eastern_date(C)` and evidence of a final result strictly before `C`. This prevents admission of a game that started yesterday and finished after the cutoff. Pregame schedule facts can describe future games if that schedule revision was visible by `C`.

A finalized status marks the league result as complete. It is separate from whether BIL reconciled the game and from when a source revision was available. Later corrections append a revision with independent availability evidence, and a retraction hides the record from cutoffs where it is visible. A corrected score or substitution yields a new coherent event stream. Historical selections and joins use the visible version of each record, with exact stream revision for the stream's children. For deterministic derived facts, eligibility is bounded by the latest availability of every required source revision, crosswalk and correction. Unknown input availability propagates to unknown. Record build time separately from that bound. A historical reconstruction generated after `C` can recreate eligible inputs. A prospective claim requires an output produced and frozen before outcome observation.

For the game-agnostic EPM reference, the rating date is an Eastern NBA date. The input view uses the start of that date in Eastern time as `C` and additionally requires `observed_date < rating_date` for games. This BIL convention implements the documented exclusion of same-date games. Exact vendor production timing is open. [EPM methodology](research/epm-methodology.md) [Primary methodology][epm]

## Game and event schemas

| Table and logical key | Fields and constraints |
| --- | --- |
| `game`, `game_id: id` | Version fields. `league: enum{NBA}`, `season_start_year: i16`, `season_type` as above, `game_date: date`, `date_basis: enum{scheduled,played}`, `home_team_id: id`, `away_team_id: id`, `neutral_site: bool?`, `status: enum{scheduled,postponed,in_progress,final,cancelled}`, `scheduled_tip_at: instant?`, `actual_tip_at: instant?`, `finalized_at: instant?`, `home_final: i16?`, `away_final: i16?`. Home and away differ. `final` requires nonnegative final scores and a played date. Other statuses leave final scores null. A known actual tip precedes a known finalization. |
| `game_supersession`, `prior_game_id: id` | Version fields and `replacement_game_id: id`. A visible relation suppresses the earlier ID in the active schedule. Retain the earlier ID and its history for provenance. Its availability includes evidence of both the replacement's issuance and the explicit relation. |
| `game_stream`, `game_id: id` | Version fields. `official_game_revision: i32`, `parser_version: id`, `reconciliation_view_id: id?`, `observed_date: date`, `complete: bool`, `quality: enum{unchecked,accepted,quarantined}`, `event_count: i32`. Its availability includes all source and adjudication evidence. `official_game_revision` and `reconciliation_view_id` pin the exact official game and selected box/appearance revisions when used. Exclude a stream from accepted output when a newer visible input changes reconciled fields and validation is pending. Pregame schedule and final box inputs can be read independently. |
| `event`, `(game_id: id, stream_revision: i32, seq: i32)` | `period: i16`, `remaining_ms: i32?` (source display), `elapsed_ms: i32?` (reconciled game time), `observed_at: instant?`, `kind: enum{period_start,period_end,shot,free_throw,rebound,turnover,foul,violation,jump_ball,substitution,timeout,replay,other}`, `team_id: id?`, `home_delta: i16`, `away_delta: i16`, `revises_seq: i32?`, `source_event_id: text?`, `source_refs: source_ref[]`. `revises_seq` refers to an earlier event in this stream when attribution is verified. |
| `event_actor`, `(game_id: id, stream_revision: i32, seq: i32, slot: i16)` | `role: enum{shooter,assist,block,steal,rebound,jump,sub_in,sub_out,fouling,fouled,other}`, `player_id: id?`, `team_id: id?`, `source_slot: text?`, `raw_actor_id: text?`. Preserve unresolved/raw actor IDs without treating them as player IDs. A valid substitution has one `sub_out` and one `sub_in`, with distinct resolved players on the same team. |

Apply supersession relations after resolving them independently at the cutoff. A later cancellation or disappearance of the replacement does not revive the original schedule entry. Reversal requires an evidenced revision or retraction of the relation. Reject cyclic or ambiguous replacement relationships. Ordinary schedule updates to the same ID are game revisions.

Canonical `seq` is dense from 1 through `event_count` and meaningful within a game stream revision. Preserve raw order from a pinned source and apply only supported reorderings with provenance and a quality record. Same-clock events follow validated action order. A replay ruling can increase the displayed time remaining. Keep displays and action order intact. Derive nondecreasing effective game elapsed time from the adjudicated clock, accounting for restored time before computing stint boundaries. An unresolved reset that affects duration, lineup state or scoring quarantines the stream. [NBA Rule 13][nba13]

Collapse an identical repeated source row only when its same source identity and payload give evidence of duplicate delivery. Preserve all raw locators. Distinct rows using the same source key or contradictory chronology need an explicit resolution or quarantine. V2 evidence includes exact repeats and last-score exceptions. The pilot uses V3 final-period markers and official box scores for the documented comparison. [Source validation](research/nba-source-validation.md#pilot-game-and-schema-checks)

## Lineups, stints, possessions and scoring

All tables in this section share the parent key `(game_id: id, stream_revision: i32)`. Sequence intervals are half-open `[start_seq, end_seq)` and use the boundary immediately before the named event. `event_count + 1` is the final boundary, with clock time taken from the final period end. The first event in the next period marks the boundary after the last event in the previous period. A substitution at event `s` updates the state for following events, so the new stint can start at `s + 1` with reconciled elapsed time from the substitution itself. At identical clock times retain any intermediate lineup needed to attach a scoring or live action. Adjacent dead-ball changes may share a boundary if no intervening live or scored action needs that state. Never assign five players by name alone.

| Table and additional key | Fields and constraints |
| --- | --- |
| `lineup`, `lineup_id: id` | `team_id: id`, `player_ids: id[]` (five distinct IDs sorted lexically). Unique team and player set within the stream. Lineup IDs are local to the stream and may be deterministic over team and sorted IDs. |
| `stint`, `stint_seq: i32` | `period: i16`, `start_seq: i32`, `end_seq: i32`, `start_elapsed_ms: i32`, `end_elapsed_ms: i32`, `home_lineup_id: id`, `away_lineup_id: id`. One row for both sides. Duration is end minus start. Nonempty sequence intervals constrain even same-clock stints. Points and possessions can be computed from the ledger at the correct grain. |
| `possession`, `possession_seq: i32` | `period: i16`, `start_seq: i32`, `end_seq: i32`, `offense_team_id: id`, `defense_team_id: id`, `end_reason: enum{made_shot,defensive_rebound,turnover,final_free_throw,period_end,jump_ball,other}`, `status: enum{accepted,excluded,unresolved}`. Document excluded intervals in the exception report. A possession can intersect multiple stints. Retained-ball points can be outside the main possession or allocated under a recorded rule. |
| `score_allocation`, `(seq: i32, scoring_team_id: id)` | `points_delta: i16` (nonzero), `possession_seq: i32?`, `credited_stint_seq: i32?`, `possession_reason: enum{control_possession,unassigned_dead_ball,unresolved}`, `attribution_rule: id`. Each scoring-side delta has one allocation. For `control_possession`, require a possession whose offense is the scoring team. For other reasons, leave the possession null. A replay correction can point to an earlier possession or stint with verified attribution. Distinguish the actual lineup for the scoring event from the credited lineup used for official player plus-minus reconciliation. |
| `quality_issue`, `issue_seq: i32` | `domain: enum{identity,chronology,lineup,score,possession,comparison}`, `code: id`, `severity: enum{warning,quarantine}`, `event_seq: i32?`, `detail: text`, `source_refs: source_ref[]`. Include safe evidence pointers and counts in the pilot report. Keep unresolved records and original inputs traceable. |

Acceptance checks for complete game streams:

1. **Timing and lineups.** Periods are 12 minutes in regulation and five in overtime. Required starter states, clock and substitutions must be supported by source evidence. Stint intervals are ordered and cover the complete stream without overlap or uncovered game-clock time. Five distinct, eligible players from each correct team share the clock. At the game level, each team's sum of player minutes is five times the played game-clock duration. Compare to official minutes with an explicit source rounding tolerance and report per-player mismatches. A zero-duration stint contributes zero time, and its supported scoring attribution remains visible. [NBA Rule 3][nba3] [NBA Rule 5][nba5]
2. **Score reconciliation.** Cumulative home and away event deltas begin at zero and reach verified final totals. Each scoring-side delta appears exactly once in the allocation table. Assigned and unassigned points together reconcile for each team. Preserve replay adjustments and retained-ball free throws without accidentally opening or ending a possession. A selected official plus-minus attribution convention must reconcile player totals or record exceptions. [NBA Rule 9][nba9] [Source validation](research/nba-source-validation.md)
3. **Possession sequence.** Order `possession_seq` densely within the stream with nonoverlapping intervals contained in one period, valid opposing teams, and a documented end reason. Gaps for dead-ball intervals are valid. Back-to-back offenses across periods or retention cases are possible. An interval spanning a lineup change still represents one possession. Compare offensive point allocations and opportunities using documented counting and exclusion rules. The downstream RAPM representation is a separate decision.
4. **Quality and reconciliation.** Mark unresolved identity, unexplained score differences, or invalid lineup/possession state as quarantined for canonical training input. Keep source material, record per-game issues and report accepted/excluded counts separately. Track independent checks by game and domain instead of inferring lineup accuracy from matching final scores.

## Box scores, tracking and feature snapshots

`metric_def` is keyed by `(metric_code: id, definition_version: i32)`. Fields `grain: enum{team_game,player_game,player_tracking,matchup}`, `unit: text`, `meaning: text`, `exposure_definition: text?`, `role_definition: text?`, and `family_code: id` specify source-normalized meaning. Distinct definitions get a new version or metric code. A source field name alone cannot establish equivalence across eras or feeds.

| Table and logical key | Fields and constraints |
| --- | --- |
| `appearance`, `(game_id: id, player_id: id)` | Version fields. `team_id: id`, `observed_date: date`, `status: enum{played,dnp,inactive,unknown}`, `started: bool?`. Missing appearance rows carry no inference about DNP. |
| `team_game_stat`, `(game_id: id, team_id: id, metric_code: id, definition_version: i32)` | Version fields plus the observation payload below. |
| `player_game_stat`, `(game_id: id, player_id: id, metric_code: id, definition_version: i32)` | Version fields plus the observation payload, and `team_id: id` from the game appearance. The box-score pilot needs count metrics, `minutes_ms` and signed `plus_minus`. |
| `player_tracking`, `(game_id: id, player_id: id, metric_code: id, definition_version: i32)` | Version fields plus the observation payload and `team_id: id`. Use definitions with game-level evidence. A season aggregate is a different grain and cannot be expanded into daily inputs. |
| `matchup_tracking`, `(game_id: id, subject_player_id: id, other_player_id: id, metric_code: id, definition_version: i32)` | Version fields plus the observation payload. Distinct roles are ordered and defined by the metric. Resolve the source direction before aggregating or comparing values. |
| `tracking_coverage`, `(game_id: id, family_code: id)` | Version fields. `status: enum{reported,partial,missing,not_checked}`, `observed_date: date`, `reason: text?`. Reported game coverage alone does not establish complete players or play opportunities. |
| `feature_snapshot`, `snapshot_id: id` | `as_of_at: instant`, `rating_date: date?`, `context_game_id: id?`, `mode: enum{game_agnostic,game_specific}`, `feature_spec_version: id`, `input_view_id: id`, `reconstruction: enum{strict,retrospective}`, `generated_at: instant`. `input_view_id` identifies the immutable selected versions and source manifest. Require context game only for game-specific mode. |
| `feature_value`, `(snapshot_id: id, player_id: id, feature_code: id)` | `value: f64?`, `numerator: decimal?`, `denominator: decimal?`, `status: enum{observed,estimated,unavailable}`. `unavailable` has null value. Use feature-spec rules for a zero denominator or a cold start. A snapshot depends on the exact input versions and feature configuration. |

The common observation payload is `observed_date: date`, `observed_at: instant?`, `value: decimal?`, `numerator: decimal?`, `denominator: decimal?`, and `status: enum{observed,unavailable,not_applicable}`. Observed values are nonnull and other statuses have null values. Exposure and denominator values are nonnegative. Count-like metrics require integral values unless defined otherwise. A missing feed is marked by coverage, a DNP by appearance, and an undefined rate by unavailable value with known zero exposure if measured. A ratio with measured components requires both numerator and denominator, including when observed zero exposure makes the rate unavailable. An entirely missing observation can lack both components. Bill Mill logs omit nonparticipants. Official box scores arbitrate player-level discrepancies. ## Fixtures and test plan

The [synthetic stream fixture](../tests/fixtures/data_contracts/synthetic_game.json) uses synthetic IDs and includes scoring, a replay clock restoration, a retained-ball point, a same-clock substitution within a possession, and a regulation final. Its deliberately sparse events exercise structural invariants for pilot tests. The fixture's source records and observation dates are fabricated. It carries no NBA game data.

| Fixture or mutation | Test tier and expected assertion |
| --- | --- |
| Valid synthetic game | Integration. Assert dense event sequence, one lineup interval per event, correct post-substitution state, one possession across the substitution, and assigned plus unassigned points matching the final. Check team minutes from stints, and eligibility of the visible final stream. |
| V2 exact repeated row, then differing payload under the same source key | Unit. Exact repeats collapse to one event with both locators. A conflicting row requires a resolved ordering/correction or quarantine. Re-running normalization yields identical output for the same pinned inputs. |
| Out-of-order same-clock substitution and make/free throw | Integration. Require evidence for sequence repair. Retain the lineup state through intervening scoring actions. Reject a duplicate entrant, wrong team or missing period starters. |
| Clock restoration before a same-clock free throw and substitution | Integration. Preserve the foul at displayed 11:56 and the later replay at 11:57. Reconcile both to 3,000 ms played and retain the displayed clock for audit. The free throw stays on the pre-substitution lineup and stints still sum to 48 minutes. |
| Live and retained-ball free throws, lane violation, replay takes away a point | Unit/integration. Test possession closure only for the stipulated control change, allow unassigned scoring with reason, reverse the correct score attribution once, and preserve prior visible stream at a cutoff before the correction. |
| End-of-period heave, rebound and jump ball, two overtimes | Integration. Keep play order and period closure. Assert exact elapsed-clock arithmetic, stint minutes, and total score at the overtime final. Test a zero-duration interval with a supported scoring event. |
| Provider ID collision, team relocation/trade, play-in code, delayed/cancelled game | Unit. Keep identity across name/team changes, isolate non-NBA IDs, exclude play-in from the pilot, and reject ambiguous matches. A new schedule or cancellation changes visibility only at its available time. |
| Final result, correction, and retraction straddling a cutoff | Unit/integration. Use the timeline below. Apply the same version filter to crosswalks and observation revisions. Confirm an unknown older archive is available for retrospective checks with an explicit flag. |
| Matchups missing a game, observed zero attempts, undefined percentage | Unit. Keep missing coverage, a true zero, and unavailable rate as distinct inputs. Never impute full league or player coverage from one observed row. |
| Pinned 2022–23 regular and playoff samples | Integration within issue #5. Compare event/reconstructed game IDs, final scores, minute budgets, player minutes and plus-minus, independent parser anomalies, and official box-score arbitration. Validate reported counts and reasons by season type. Use only data approved for the intended purpose and keep input snapshots out of Git. [Observed audit checks](research/nba-source-validation.md) |
